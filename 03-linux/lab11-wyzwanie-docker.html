🐳 Wyzwanie 4: Wstęp do DevOps

Koniec z ciężkimi maszynami wirtualnymi. Czas na Kontenery (Docker)!

Cel Wyzwania (Boss Fight): Zrozumieć, jak działa nowoczesne IT. Zainstalujemy silnik Docker i uruchomimy w pełni funkcjonalny serwer WWW w odizolowanym kontenerze za pomocą zaledwie jednej komendy.
Czym różni się Kontener od Maszyny Wirtualnej?

Maszyna Wirtualna (np. VirtualBox): Emuluje cały sprzęt (płytę główną, dysk, RAM) i instaluje na nim pełny, ciężki system operacyjny (np. Windows Server ważący 15 GB). Uruchamia się kilka minut.

Kontener (Docker): Nie emuluje sprzętu. Współdzieli jądro (kernel) z systemem gospodarza (Twoim Ubuntu). Pakuje tylko samą aplikację (np. serwer WWW) i jej niezbędne biblioteki. Waży kilka megabajtów i uruchamia się w ułamek sekundy!

Krok 1: Instalacja Silnika (Docker Engine)

Czas: 5 min

Aby uruchamiać kontenery, potrzebujemy programu zarządzającego – silnika Docker. W Ubuntu instalacja jest bardzo prosta.

# 1. Zaktualizuj pakiety i zainstaluj Dockera (pobierze ok. 100-200 MB) sudo apt update sudo apt install docker.io -y # 2. Sprawdź, czy silnik działa i włącza się po restarcie sudo systemctl enable --now docker sudo systemctl status docker

(Wciśnij 'q', aby wyjść ze statusu).

Krok 2: Magia jednej komendy (Run)

Czas: 5 min

W Wyzwaniu 3 instalowaliśmy Nginxa bezpośrednio na naszym systemie. Teraz uruchomimy inny serwer WWW (Apache - httpd), ale zamkniemy go w kontenerze.

# Uruchom kontener z serwerem Apache # Flagi: -d (działaj w tle/detached), -p (przekieruj port 8080 z Ubuntu na port 80 w kontenerze), --name (nazwij kontener) sudo docker run -d -p 8080:80 --name moj_serwer httpd

Co się właśnie stało?

  1. Docker zauważył, że nie masz obrazu httpd na dysku.
  2. Szybko pobrał go z internetu (z Docker Hub).
  3. Stworzył z niego odizolowany kontener.
  4. Uruchomił go w tle i połączył port 8080 Twojego Ubuntu z portem 80 wewnątrz kontenera.

Wszystko to w kilka sekund!

Krok 3: Weryfikacja i Test z Windowsa

Czas: 5 min
# Sprawdź listę działających kontenerów sudo docker ps

Zobaczysz tabelę, w której widnieje Twój kontener moj_serwer oraz informacja o portach: 0.0.0.0:8080->80/tcp.

  • Test z Windowsa: Przejdź na maszynę Windows 11. Otwórz przeglądarkę i wpisz adres IP Linuxa, ale tym razem z portem 8080:
    http://192.168.10.20:8080
  • Powinieneś zobaczyć wielki napis It works! (To domyślna strona serwera Apache).
🚨 Zapora UFW (Przypomnienie): Jeśli w Wyzwaniu 2 włączyłeś zaporę UFW, musisz odblokować port 8080, aby Windows mógł się połączyć!
sudo ufw allow 8080/tcp

Krok 4: Zarządzanie Kontenerami

Czas: 5 min

Kontenery są "jednorazowe". Jeśli coś zepsujesz, po prostu usuwasz kontener i stawiasz nowy w 3 sekundy.

# 1. Zatrzymanie kontenera (strona WWW przestanie działać) sudo docker stop moj_serwer # 2. Usunięcie kontenera (bezpowrotnie kasuje kontener, ale obraz httpd zostaje na dysku) sudo docker rm moj_serwer # 3. Sprawdź, czy kontener zniknął sudo docker ps -a

🕵️‍♂️ Sekret Inżyniera: Dlaczego Docker zmienił świat?

Kiedyś programiści mówili: "U mnie na komputerze działa, nie wiem dlaczego na serwerze nie działa". Docker rozwiązał ten problem. Programista pakuje swoją aplikację do kontenera razem ze wszystkimi bibliotekami. Jeśli kontener działa na laptopie programisty, zadziała dokładnie tak samo na serwerze testowym, produkcyjnym i w chmurze AWS. To fundament kultury DevOps (Development + Operations).
