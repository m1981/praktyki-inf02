🌟 Wyzwanie 2: Twierdza Linux

Zapora sieciowa (UFW) i aktywna obrona przed atakami (Fail2ban)

Cel Wyzwania: Zabezpieczyć serwer przed nieautoryzowanym dostępem. Skonfigurujemy zaporę sieciową z poziomu terminala, a następnie zainstalujemy "strażnika", który będzie automatycznie blokował hakerów próbujących odgadnąć nasze hasło.

Krok 1: Podnoszenie Tarcz (UFW)

Czas: 10 min

W Windowsie używaliśmy graficznej przystawki wf.msc. W Ubuntu standardowym narzędziem do zarządzania zaporą jest UFW (Uncomplicated Firewall - Nieskomplikowana Zapora).

🚨 KRYTYCZNY KROK (Nie odetnij się!): Domyślnie UFW blokuje cały ruch przychodzący. Jeśli włączysz zaporę teraz, natychmiast stracisz połączenie SSH z serwerem! Najpierw musimy zrobić "dziurę" w zaporze dla naszego portu SSH (w Labie 5 zmieniliśmy go na 2222). 
      # 1. Sprawdź status zapory (powinna być nieaktywna - inactive)
      sudo ufw status

      # 2. Zezwól na ruch przychodzący na porcie 2222 (protokół TCP)
      sudo ufw allow 2222/tcp

      # 3. Włącz zaporę (system ostrzeże Cię o możliwym przerwaniu połączeń SSH - wciśnij
       'y')
      sudo ufw enable

      # 4. Sprawdź status ponownie. Zobaczysz swoją aktywną regułę!
      sudo ufw status

Krok 2: Aktywna Obrona (Fail2ban)

Czas: 10 min

Zapora UFW to obrona bierna – po prostu wpuszcza ruch na porcie 2222. Ale co, jeśli ktoś (lub bot) zacznie zgadywać nasze hasło, wysyłając 1000 zapytań na sekundę (atak Brute-Force)? Potrzebujemy Fail2ban. 

      # 1. Zaktualizuj listę pakietów i zainstaluj Fail2ban
      sudo apt update sudo apt install fail2ban -y

      # 2. Sprawdź, czy usługa działa (powinna uruchomić się automatycznie)
      sudo systemctl status fail2ban

🕵️‍♂️ Sekret Inżyniera: Jak działa Fail2ban?

Pamiętasz Lab 6, gdzie używaliśmy grep do szukania słowa "Failed" w pliku /var/log/auth.log? Fail2ban to po prostu skrypt, który robi to samo, ale automatycznie i w czasie rzeczywistym! Jeśli zauważy, że z jednego adresu IP przyszło np. 5 błędnych haseł w ciągu 10 minut, natychmiast dodaje ten adres IP do "czarnej listy" w zaporze UFW na określony czas (np. 10 minut).

Krok 3: Symulacja Ataku (Z Windowsa)

Czas: 10 min

Przetestujmy naszego strażnika. Wcielimy się w rolę hakera atakującego z maszyny Windows 11.

  • Na Windowsie: Otwórz CMD i spróbuj zalogować się na Linuxa. 
    ssh -p 2222 administrator@192.168.10.20
  • Gdy system zapyta o hasło, wpisz błędne hasło i wciśnij Enter.
  • Powtórz tę czynność (wpisywanie błędnego hasła) około 5-6 razy.
  • Efekt: Nagle terminal "zawiśnie" lub wyrzuci błąd Connection timed out / Connection refused. Nie będziesz mógł nawet spingować serwera! Zostałeś zbanowany.

Krok 4: Analiza i Ułaskawienie (Na Linuxie)

Czas: 10 min

Skoro Twój Windows dostał bana, nie połączysz się już przez SSH. Musisz otworzyć okno VirtualBoxa z Ubuntu (konsolę lokalną), zalogować się i sprawdzić, co się stało. 

      # 1. Sprawdź status "więzienia" (jail) dla usługi SSH
      sudo fail2ban-client status sshd

Na ekranie zobaczysz statystyki. W sekcji Banned IP list: powinien widnieć adres IP Twojego Windowsa (192.168.10.10 lub 192.168.10.30)! 

      # 2. Ułaskawienie: Zdejmij bana z adresu IP Windowsa (podmień IP na to, które widziałeś
       wyżej!)
      sudo fail2ban-client set sshd unbanip 192.168.10.10

      # 3. Sprawdź status UFW (zobaczysz, że Fail2ban zarządza regułami za Ciebie)
      sudo ufw status

Wróć na Windowsa. Połączenie SSH znów powinno działać (tym razem podaj poprawne hasło!).
