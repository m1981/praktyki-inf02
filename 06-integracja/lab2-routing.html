Routing i Translacja Adresów

Czas: 45 min
Cel: Skonfigurować usługę RRAS (NAT), aby Linux mógł połączyć się z Internetem przez Windows Server.
  • Krok 1: Dwa interfejsy (Multihoming)

    WIN_SERVER ma dwa interfejsy: Ethernet (Karta 1, WAN, NAT) z dostępem do Internetu i LAN12 (LAN) ze stałym adresem 192.168.10.10. Ważne: LAN12 nie może mieć bramy domyślnej!

    Kroki 2–3 wykonałeś w Windows Lab 5. Jeśli w rrasmgmt.msc serwer ma zieloną strzałkę i pozycję NAT – przejdź od razu do Kroku 4.

  • Krok 2: Instalacja Roli RRAS

    W Menedżerze Serwera dodaj rolę: Dostęp zdalny (Remote Access), a w jej szczegółach zaznacz Routing.

  • Krok 3: Konfiguracja NAT

    Otwórz przystawkę Routing i dostęp zdalny (rrasmgmt.msc). Kliknij prawym przyciskiem myszy na nazwę serwera i wybierz Konfiguruj i włącz.... W kreatorze wybierz Translacja adresów sieciowych (NAT). Następnie wskaż Ethernet (Karta 1, WAN) jako interfejs publiczny podłączony do Internetu.

  • Krok 4: Konfiguracja Klienta (Linux)

    1. Wypnij kabel Karty 1 LINUX_SERVER: w oknie maszyny Devices ➔ Network ➔ odznacz Connect Network Adapter 1. Bez tego Linux nadal wychodziłby do Internetu przez NAT VirtualBoxa, a nie przez Twój serwer.

    2. Otwórz plik Netplan – ten sam, który edytowałeś w Linux Lab 4. Jeśli nazywa się inaczej niż poniżej, sprawdź nazwę komendą ls /etc/netplan/: 

    sudo nano /etc/netplan/50-cloud-init.yaml

    Usuń całą zawartość pliku i wpisz dokładnie ten tekst. Wcięcia robisz tylko spacjami (nigdy klawiszem TAB):

    Różnica względem Integracji Lab 1: doszła sekcja routes (brama).

    network:
  version: 2
  ethernets:
    enp0s3:
      dhcp4: yes
      optional: true
      dhcp4-overrides:
        use-dns: no
    enp0s8:
      dhcp4: no
      addresses: [192.168.10.20/24]
      routes:
        - to: default
          via: 192.168.10.10
      nameservers:
        addresses: [192.168.10.10]

    3. Zapisz (Ctrl+O, Enter, Ctrl+X), zastosuj zmianę i sprawdź trasę:

    sudo netplan apply
ip route

    Oczekiwany wynik: linia default via 192.168.10.10 dev enp0s8 i brak linii z 10.0.2.2.

  • Krok 5: Wielki Test (Ping w świat)

    Otwórz terminal na LINUX_SERVER i wpisz: ping 8.8.8.8. Jeśli pakiety wracają, oznacza to, że Windows Server poprawnie tłumaczy adresy (NAT) i wypuszcza Linuxa w świat!

🚨 HACZYKI EGZAMINACYJNE (Arkusz 24.01):
  • Dwie Bramy Domyślne: To najczęstszy błąd! Windows Server nie może mieć wpisanej bramy domyślnej na karcie LAN. Brama domyślna może być tylko jedna w całym systemie (na karcie WAN). Jeśli wpiszesz dwie, tablica routingu zwariuje i NAT nie zadziała.
  • Brak Bramy na LINUX_SERVER: Jeśli zapomnisz wpisać 192.168.10.10 jako bramę w ustawieniach Ubuntu, Linux nie będzie wiedział, komu przekazać pakiety przeznaczone do Internetu. Zwróci błąd Network is unreachable.
  • Zły interfejs w kreatorze RRAS: Kreator pyta o interfejs publiczny (podłączony do Internetu). Jeśli przez pomyłkę wskażesz tam kartę LAN, zablokujesz cały ruch.
💡 Pro-Tip od DevOpsa: Chcesz zobaczyć magię routingu na własne oczy? Na LINUX_SERVER wpisz komendę traceroute 8.8.8.8 (lub tracepath 8.8.8.8). Zobaczysz, że pierwszym "przystankiem" (hop) Twoich pakietów jest adres IP Windows Servera (192.168.10.10), a dopiero potem lecą one do dostawcy Internetu.
