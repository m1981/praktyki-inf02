Wielki Test Połączenia

Czas: 45 min
Cel: Udowodnić, że LINUX_SERVER potrafi korzystać z usług Web i DNS hostowanych na WIN_SERVER.
  • Krok 1: Instalacja Ról (Windows)

    Role Serwer DNS i Serwer sieci Web (IIS) zainstalowałeś w Windows Lab 1 i 4. Sprawdź w Menedżerze Serwera, że obie są na liście – wtedy przejdź do Kroku 2.

  • Krok 2: Konfiguracja DNS (Windows)

    Otwórz przystawkę DNS. Utwórz nową Strefę wyszukiwania do przodu o nazwie egzamin.local. Wewnątrz strefy dodaj nowy Rekord A (Host) o nazwie www, wskazujący na adres IP tego Windows Servera.

  • Krok 3: Konfiguracja IIS (Windows)

    Utwórz folder C:\www i stwórz w nim plik index.html z dowolnym tekstem. Otwórz Menedżer IIS, dodaj nową witrynę wskazującą na ten folder. W oknie Wiązania (Bindings) w polu Nazwa hosta wpisz koniecznie: www.egzamin.local.

  • Krok 4: Konfiguracja Sieci Klienta (Linux)

    Otwórz plik Netplan – ten sam, który edytowałeś w Linux Lab 4. Jeśli nazywa się inaczej niż poniżej, sprawdź nazwę komendą ls /etc/netplan/: 

    sudo nano /etc/netplan/50-cloud-init.yaml

    Usuń całą zawartość pliku i wpisz dokładnie ten tekst. Wcięcia robisz tylko spacjami (nigdy klawiszem TAB): 

    network:
  version: 2
  ethernets:
    enp0s3:
      dhcp4: yes
      optional: true
      dhcp4-overrides:
        use-dns: no
    enp0s8:
      dhcp4: no
      addresses: [192.168.10.20/24]
      nameservers:
        addresses: [192.168.10.10]

    Zapisz (Ctrl+O, Enter, Ctrl+X), zastosuj zmianę i sprawdź DNS:

    sudo netplan apply
resolvectl query www.egzamin.local

    Oczekiwany wynik: www.egzamin.local: 192.168.10.10.

    🕵️‍♂️ Sekret Inżyniera: co robią linijki use-dns i optional?
    • use-dns: no – Linux nie bierze DNS od VirtualBoxa (z Karty 1) i pyta wyłącznie WIN_SERVER. Dzięki temu nazwy z egzamin.local zawsze się rozwiążą. Internet nadal działa: WIN_SERVER przekazuje pozostałe zapytania dalej (forwarder z Windows Lab 1).
    • optional: true – start systemu nie czeka na kartę enp0s3. Bez tego, gdy kabel Karty 1 jest wypięty (od Integracji Lab 2), Ubuntu przez 2 minuty pokazuje A start job is running for Wait for Network to be Configured.
  • Krok 5: Wielki Test (Linux)

    Ubuntu Server nie ma przeglądarki – użyj terminala: curl http://www.egzamin.local. Na ekranie zobaczysz treść Twojego pliku index.html.

🚨 HACZYKI EGZAMINACYJNE (Arkusze 24.01, 25.01):
  • Zapora (Firewall): Strona się nie ładuje (Timeout)? Windows domyślnie blokuje ruch z zewnątrz! Musisz wejść w wf.msc na WIN_SERVER i utworzyć regułę przychodzącą zezwalającą na ruch na porcie 80 (TCP).
  • Uprawnienia NTFS: Widzisz błąd 401/403 (Brak dostępu) w przeglądarce? Sprawdź, czy folder C:\www ma w zakładce Zabezpieczenia dodane uprawnienia "Odczyt" dla grupy Użytkownicy (lub IIS_IUSRS).
💡 Pro-Tip od DevOpsa: Zamiast klikać w przeglądarkę, otwórz terminal na LINUX_SERVER i wpisz curl -v http://www.egzamin.local. Zobaczysz dokładnie, czy problem leży w DNS (nie potrafi rozwiązać nazwy), czy w zaporze (brak połączenia), czy w uprawnieniach (kod HTTP 403).
