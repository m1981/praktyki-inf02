Montowanie udziałów Windows (SMB/CIFS) w drzewie Linuxa

🗺️ Faza 4 – zanim zaczniesz: ustaw maszyny według Mapy Architektury, Faza 4.
  • Włącz: LINUX_SERVER, WIN_SERVER.
  • Wyłącz: WIN_11.
  • Wymagane wcześniej: Integracja Lab 4.
🪟 Windows Server Udział: \\192.168.10.10\Backup$
Protokół SMB
➔
🐧 Ubuntu Server Katalog: /mnt/backup

Krok 1: Przygotowanie gruntu (Windows)

Czas: 10 min
Cel: Utworzenie ukrytego folderu na WIN_SERVER, który będzie służył jako magazyn na kopie zapasowe z LINUX_SERVER.
  • Tworzenie folderu: Na dysku C:\ w Windows Serverze utwórz folder o nazwie Kopie_Linux.
  • Udostępnianie (Share): Kliknij prawym przyciskiem myszy na folder ➔ Właściwości ➔ Udostępnianie ➔ Udostępnianie zaawansowane.
  • Ukryty udział: Zaznacz "Udostępnij ten folder". W polu Nazwa udziału wpisz Backup$ (znak dolara ukryje go w sieci).
  • Uprawnienia: Kliknij przycisk Uprawnienia. Upewnij się, że grupa Wszyscy (Everyone) ma zaznaczoną Pełną kontrolę. (Pamiętaj, że prawdziwe bezpieczeństwo i tak zapewniają uprawnienia NTFS w zakładce Zabezpieczenia, gdzie Administrator ma pełnię praw).

Krok 2: Narzędzia i Punkt Montowania (Linux)

Czas: 10 min
Cel: Zainstalowanie pakietów obsługujących protokół Microsoftu oraz przygotowanie "drzwi" do Windowsa.
Czym jest Punkt Montowania (Mount Point)?

W Windowsie, gdy podłączasz dysk sieciowy, dostaje on nową literę (np. Z:\). W Linuxie nie ma liter dysków! Wszystko musi być podpięte do głównego drzewa katalogów (zaczynającego się od /).

Punkt montowania to po prostu pusty folder w Linuxie. Kiedy "zamontujesz" w nim udział z WIN_SERVER, ten folder staje się magicznym portalem. Cokolwiek do niego wrzucisz, fizycznie poleci kablem sieciowym na dysk Windowsa! 

      # 1. Zaktualizuj listę pakietów i zainstaluj narzędzia CIFS (Common Internet File System -
       protokół Windowsa)
      sudo apt update
      sudo apt install cifs-utils -y

      # 2. Utwórz pusty katalog, który będzie naszym "portalem" (zwyczajowo robimy to w katalogu
       /mnt)
      sudo mkdir -p /mnt/backup

Krok 3: Rzucanie mostu (Montowanie)

Czas: 15 min
Cel: Połączenie pustego katalogu w LINUX_SERVER z udostępnionym folderem na WIN_SERVER.

Teraz wykonamy najważniejszą komendę. Zastąp 192.168.10.10 adresem IP swojego Windows Servera! 

      # Składnia: sudo mount -t cifs -o username=USER,password=HASLO //IP_SERWERA/UDZIAL
       /PUNKT_MONTOWANIA
      sudo mount -t cifs -o username=Administrator,password=ZAQ\!2wsx //192.168.10.10/Backup$
      /mnt/backup
🚨 Najczęstsze błędy (Ukośniki i Znaki Specjalne):
  • Ukośniki: W Windowsie ścieżki sieciowe piszemy backslashem (\\192...). W Linuxie ZAWSZE używamy zwykłego slasha (//192...).
  • Wykrzyknik w haśle: Zauważyłeś backslash \ przed wykrzyknikiem w haśle ZAQ\!2wsx? W Linuxie wykrzyknik to znak specjalny (odwołuje się do historii komend). Aby system potraktował go jako zwykłą literę hasła, musimy go "uciec" (escape) dodając przed nim \.
  • Wielki Test: Sprawdźmy, czy most działa! Będąc na LINUX_SERVER, stwórzmy plik w naszym portalu: 
      # Wejdź do zamontowanego katalogu
      cd /mnt/backup

      # Utwórz plik tekstowy (wymaga sudo, bo udział zamontował root)
      sudo touch kopia_z_linuxa.txt
      sudo sh -c 'echo "Witaj Windowsie, tu Linux!" >
      kopia_z_linuxa.txt'

Teraz przejdź na maszynę WIN_SERVER. Otwórz folder C:\Kopie_Linux. Plik kopia_z_linuxa.txt powinien tam na Ciebie czekać!

Krok 4: Automatyzacja (fstab)

Czas: 10 min

🕵️‍♂️ Sekret Inżyniera: Trwałość po restarcie

Komenda mount działa tylko do momentu wyłączenia komputera. Po restarcie Linuxa, most zniknie! W prawdziwej pracy DevOpsa musimy sprawić, by udział montował się automatycznie przy każdym starcie systemu.

Służy do tego plik /etc/fstab (File System Table).

       # Otwórz plik fstab w edytorze nano
       sudo nano /etc/fstab

Na samym dole pliku dopisuje się linijkę (nie rób tego teraz, jeśli nie czujesz się pewnie, bo błąd w tym pliku może uniemożliwić start Linuxa!): 

//192.168.10.10/Backup$  /mnt/backup  cifs  username=Administrator,password=ZAQ!2wsx  0  0

Pro-Tip Bezpieczeństwa: Wpisywanie hasła jawnym tekstem w pliku fstab to zła praktyka. Profesjonaliści tworzą ukryty plik z poświadczeniami (np. /root/.smbcredentials) i w fstabie odwołują się tylko do niego za pomocą opcji credentials=/root/.smbcredentials.
